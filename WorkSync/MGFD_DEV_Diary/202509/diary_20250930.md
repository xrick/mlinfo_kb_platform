# MGFD開發日誌 - 2025年9月30日

## 問題概述

用戶反饋查詢「請給我8329的資料」時，系統回覆「抱歉，根據目前的產品資料庫中並沒有「8329」這個型號」，但當用戶查詢「請給我8329的規格」時，系統卻能正確回覆8329的產品資訊。

## 問題表現

- **查詢1**: 「請給我8329的資料」→ 系統回覆：找不到8329的資料
- **查詢2**: 「請給我8329的規格」→ 系統回覆：正確顯示8329產品資訊

## 技術問題診斷

### 1. 系統處理流程分析

通過分析 `libs/KnowledgeManageHandler/knowledge_manager.py` 中的 `_extract_product_codes` 函數，發現問題出現在產品代碼檢測的四重安全閘門機制：

#### 四重安全閘門檢測機制

1. **Layer 1**: 字母+數字模式（如 APX819, AKK839）
2. **Layer 2**: 純數字模式（如 819, 8329）
3. **Layer 3**: 上下文關鍵詞驗證
4. **Layer 4**: 資料庫存在性驗證

### 2. 問題根源分析

問題出現在 **Layer 3: 上下文關鍵詞驗證** 階段：

```python
# 在 _extract_product_codes 函數中的上下文關鍵詞列表
context_keywords = [
    '機型', '型號', '機種', '類別',
    '系列','產品', '筆電', '筆記型電腦',
    'laptop', 'notebook', '規格', 'spec',
    'cpu', 'gpu', '處理器', '差異', '比較', '對比', 'vs'
]
```

**關鍵發現**：

- 「規格」在 `context_keywords` 列表中 ✅
- 「資料」不在 `context_keywords` 列表中 ❌

### 3. 處理流程差異

1. **「請給我8329的規格」**：
   - 8329 被檢測為純數字產品代碼
   - 「規格」通過上下文關鍵詞驗證
   - 通過資料庫存在性驗證
   - 成功觸發產品搜尋流程

2. **「請給我8329的資料」**：
   - 8329 被檢測為純數字產品代碼
   - 「資料」無法通過上下文關鍵詞驗證
   - 被過濾掉，不觸發產品搜尋流程
   - 回傳「找不到資料」

## 解決方案

### 方案1：擴展上下文關鍵詞（推薦）

在 `libs/KnowledgeManageHandler/knowledge_manager.py` 的 `_extract_product_codes` 函數中，擴展 `context_keywords` 列表：

```python
context_keywords = [
    '機型', '型號', '機種', '類別',
    '系列','產品', '筆電', '筆記型電腦',
    'laptop', 'notebook', '規格', 'spec',
    '資料', '資訊', '內容', '詳情', '介紹',  # 新增
    'cpu', 'gpu', '處理器', '差異', '比較', '對比', 'vs'
]
```

### 方案2：優化查詢意圖識別

在 `libs/UserInputHandler/UserInputHandler.py` 中增強對「資料」查詢的識別，確保這類查詢也能觸發產品搜尋流程。

### 方案3：改進產品代碼檢測邏輯

降低純數字產品代碼檢測的門檻，或者增加更智能的上下文分析，減少對特定關鍵詞的依賴。

## 實作建議

### 立即修復（方案1）

1. 修改 `libs/KnowledgeManageHandler/knowledge_manager.py` 第1647-1652行
2. 在 `context_keywords` 列表中添加「資料」、「資訊」、「內容」等詞彙
3. 測試驗證修復效果

3. 增加查詢意圖識別的準確性

## 總結

這個問題反映了系統在自然語言理解上的局限性，特別是對同義詞的識別能力不足。通過擴展上下文關鍵詞庫，可以快速解決當前問題，但長期來看需要建立更智能的查詢意圖識別機制。
