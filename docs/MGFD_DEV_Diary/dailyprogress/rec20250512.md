  - 路由註冊由 `register_blueprint` → `include_router`

  - `libs/mgfd_cursor/user_input_handler.py`: 回傳鍵名 `updated_state` → `state`
  - `libs/mgfd_cursor/dialogue_manager.py`: `route_next_action` 回傳 `{ success, command }`；例外時提供回退同結構

  - `libs/mgfd_cursor/mgfd_system.py`: `ResponseGenerator` 與 `stream` 正確傳入 `action_result["result"]`
- 測試與驗證
  - 新增 `test_fastapi_migration.py`: 健康/狀態/MGFD健康/MGFD狀態/聊天/會話/歷史/API文檔/錯誤/性能 全覆蓋
  - 驗證 `/openapi.json` 路由完整性，`/api/mgfd/*` 端點皆正確註冊

### 遭遇問題與修復摘要
- 缺少 `redis` 套件 → 安裝 `pip install redis`
- Router 層級誤用 `exception_handler` → 改至 `main.py` 全域 `@app.exception_handler`
- 中間件 `uuid` 未導入 → 於 `main.py` 補上 `import uuid`
- 測試埠位不一致（5000 vs 8001）→ 更新 `BASE_URL` 為 `http://localhost:8001`
- `KeyError: 'state'`（UserInputHandler 回傳鍵名不一致）→ 統一回傳 `state`
- 對話決策回傳 `None` → DialogueManager 回傳 `{ success, command }`
- 動作執行回傳 `None` → ActionExecutor 回傳 `{ success, result }`
- Response 組裝不正確 → MGFDSystem 改傳 `action_result["result"]` 給 ResponseGenerator
- DuckDB 鎖定衝突（多進程）→ 重啟前清理舊進程；必要時可切只讀模式（暫不啟用）
